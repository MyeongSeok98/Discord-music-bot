# Discord Music Bot Local Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore the incomplete Discord music bot so it installs on Node 24, starts with validated Discord/Atlas configuration, plays music in a personal test guild, and records playback history for a future recommender.

**Architecture:** Keep the existing CommonJS and discord.js v13 command surface while extracting configuration, module loading, Mongo model initialization, and playback-history tracking into testable units. The process connects to MongoDB before logging into Discord; history writes are best-effort and never stop playback after startup succeeds.

**Tech Stack:** Node.js 24.18+, node:test, discord.js 13.17.1, @discordjs/voice 0.19.0, play-dl 1.9.7, FFmpeg static 5.3.0, Mongoose 8.24.4, MongoDB Atlas.

**Spec:** `docs/superpowers/specs/2026-09-02-discord-music-bot-local-recovery-design.md`

## Global Constraints

- Preserve CommonJS modules and the existing slash-command names.
- Keep `discord.js` on v13 for this recovery; full v14+ migration is a separate project.
- Support the installed Node.js 24.18.0 runtime.
- Never log Discord tokens, YouTube cookies, or the MongoDB URI.
- `npm test` must not require Discord or MongoDB network access.
- MongoDB history failure after startup must not interrupt playback.
- Store track metadata and Discord IDs only; do not store arbitrary message content.
- Use TDD for every production behavior: failing test, observed expected failure, minimal implementation, passing test.
- Do not commit `.env`; commit `.env.example` and `package-lock.json` when Git is initialized.

- [ ] **Step 3: Implement the minimal configuration loader**

Create `config.js` with a fixed ordered required-key list, `ConfigError`, whitespace trimming for non-secret display values, the exact defaults asserted above, and no logging. Do not parse or re-emit the URI/token.

Core implementation shape:

```js
const REQUIRED_KEYS = [
  'DISCORD_TOKEN', 'CLIENT_ID', 'DEVGUILD_ID', 'MONGODB_URI',
  'SERVERDBDIRNAME', 'PLAYERDBDIRNAME'
];

class ConfigError extends Error {
  constructor(missing) {
    super(`필수 환경변수가 없습니다: ${missing.join(', ')}`);
    this.name = 'ConfigError';
    this.missing = missing;
  }
}

function loadConfig(env = process.env) {
  const missing = REQUIRED_KEYS.filter(key => !env[key]?.trim());
  if (missing.length) throw new ConfigError(missing);
  return Object.freeze({
    discordToken: env.DISCORD_TOKEN,
    clientId: env.CLIENT_ID.trim(),
    devGuildId: env.DEVGUILD_ID.trim(),
    mongodbUri: env.MONGODB_URI,
    serverDbModel: env.SERVERDBDIRNAME.trim(),
    playerDbModel: env.PLAYERDBDIRNAME.trim(),
    announce: env.ANNOUNCE?.trim() || '음악 재생 대기 중',
    playerChannelName: env.PLAYERCHANNEL_NAME?.trim() || 'music-player',
    playerEmbedImageUrl: env.PLAYEREMBED_IMAGEURL?.trim() || '',
    defaultColor: env.DEFAULT_COLOR?.trim() || '#5865F2',
    youtubeCookie: env.YOUTUBE_COOKIE || ''
  });
}
```
